SFRA Studio · 顶栏合并方案

现在顶栏两行共 92px：第一行放指示灯/标题/串口/连接/两个 pill，第二行只放一个居中的「测量 / 补偿器」 Tab。 第二行除中间 220px 外全是空白。下面三个方案分别释放 46px、0px、46px，并给出各自的取舍。

方案 A · 完全合并成一行 省 46px推荐

把「测量 / 补偿器」直接塞进顶栏，放在标题右侧；串口那一组靠右。Tab 仍然视觉居中——用两侧等重的弹簧， 左侧弹簧吃掉"标题 + Tab 左半"的宽度差，所以哪怕窗口缩放，Tab 的中心也始终落在窗口中线附近（±6px）。

如果选 A（推荐），实现上有三个坑要提前说

坑说明
1. 居中不能靠
addStretch 简单对称		 现在 TabStrip 是「弹簧 + Tab + 弹簧」，严格居中。合并到顶栏后，左边有标题、右边有串口组， 两个弹簧的"容量"不同，Tab 会被推离中线。 解法：用一个 QGridLayout 三层结构——左区 / 中间 Tab / 右区， 给左右区相同的 stretch，中间 Tab 用 Qt.AlignCenter。 这样无论左右内容多宽，Tab 都在窗口中线。
2. 左右区宽度不等时
Tab 会被挤歪		 严格中线意味着：当右区（串口组）比左区（标题）宽很多时，Tab 左边会剩很多空间、 右边被压。视觉上察觉不到，但布局会把 Tab 往左推。 解法：给中区设 setMinimumWidth(Tab宽度 + 2×间距)， 并把左右区都设成 QSizePolicy.Expanding， 挤不下时优先压缩 pill 的可见性（见坑 3），而不是压缩 Tab。
3. 窄窗口要降级 1120px 时右侧「仿真 · Fs 100 kHz」放不下。 解法：给这个 pill 挂一个 resizeEvent 判据——可用宽 < 阈值时 setVisible(False)；把完整文案挪到 tooltip 和状态栏。 这件恰好也是 test_ui_text_fit.py 会管到的范围， 新增的顶栏控件要一并纳入那套判据（否则又会出"文字显示一半"）。
另外提醒：合并之后顶栏高度从 46 提到 52（给 Tab 的 28px 胶囊留垂直余量）， 净省 92 − 52 = 40px，不是 46px。这个数字也请一并确认。
