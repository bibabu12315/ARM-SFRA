# 02 系统架构（v3 定版 · 可开发基线）

> 三个交付件：**固件库**、**上位机**、**SOP**。本文定它们的边界、接口和职责。
> v2 变更：幅相计算上移 PC、删同扫与 CL 通道、结果数组只存累加器原值、界面砍 pzmap/一键全扫/叠加对比。

**边界原则**：
- 库不实现任何 PWM/ADC/HAL，只要求用户在正确位置插入 2~3 行调用；
- 库不改用户数据结构，所有上下文在自己的 `sfra_t` 里；
- **MCU 不做任何幅相运算**（v2）：只累加、只上报原始累加器，相位约定全项目只在 PC `bode_data.py` 一处实现（00 文档 D18）。

## 2.2 固件侧：三层结构

### 2.2.1 `sfra_core.c/h` —— 算法与状态机（纯 C99，零依赖）

**公开 API（测量定义见 01 文档 1.7）**

```c
/* ---- 生命周期 ---- */
void      sfra_init_all(void);                 // 建正弦表（仅启动时调用）
void      sfra_init(sfra_t *s, const sfra_setup_t *cfg,
                    const sfra_result_t *res);  // 配置与结果数组都由用户提供，不分配内存
int       sfra_start(sfra_t *s);               // 非阻塞；0 成功，非 0 = 参数错误码
void      sfra_abort(sfra_t *s);               // 立即置 amplitude=0（安全第一优先级）
uint8_t   sfra_is_running(const sfra_t *s);
uint8_t   sfra_is_done(const sfra_t *s);
uint8_t   sfra_state(const sfra_t *s);         // 原始状态号，调试/上位机 STATUS 用
void      sfra_clear_done(sfra_t *s);          // 取走结果后清 DONE，才允许下一轮 start

/* ---- ISR 内调用（必须快） ---- */
sfra_signal_t sfra_inject(sfra_t *s);
/* 返回 A·cosθ。LOOP 模式采集中时，同一调用里累加注入复振幅（GH 公式需要，01 文档 1.7.1）：
   Inj_c += inj·cosθ;  Inj_s += inj·sinθ;
   累加上限与 monitor() 一致（collected < data_count），否则 Inj 与 Y 点数不等。
   settle 计数也在这里递减——它是 ISR 每周期唯一必经点。 */

void sfra_monitor(sfra_t *s, sfra_signal_t in, sfra_signal_t out);
/* 累加 Y(out)；PLANT 模式还累加 X(in)；LOOP 忽略 in。
   采满 data_count 立即 return（多跑收尾不累加）。
   注意：每个 ISR 只调用一次，且必须在 inject() 之后、advance() 之前 */

void sfra_advance(sfra_t *s);
/* theta_phase += step_phase。每 ISR 周期恰好一次，**必须在 monitor() 之后** */

/* ---- 主循环调用 ---- */
void sfra_background_task(sfra_t *s, const sfra_result_t *res);
/* 只做状态机推进与换频点，不做任何幅相计算（v2：幅相在 PC） */

/* ---- 定点版：不是另一套函数 ---- */
/* 编译期定义 SFRA_USE_FIXED_POINT=1，`sfra_signal_t` 就变成 int16_t，
   inject/monitor 的签名与上面完全一致，热路径代码也是同一份。
   定点只在 I/O 边界多做一次 to_sig() 量化（float ↔ Q15），
   这样不会出现"两条路径各自演化、慢慢走偏"的老问题（A11 的教训）。 */
```

**配置结构**

```c
typedef struct {
    float isr_freq;      // 控制 ISR 频率 Hz（= f_sw）
    float freq_start;    // 扫频起点 Hz
    float freq_step;     // 每点倍数 = pow(10, 1/pts_per_dec)
    float amplitude;     // 注入幅值，per-unit (0,1)
    uint16_t vec_length; // 频点个数
    uint8_t cycles_mode; // 0=Fast 1=Normal 2=Precise
    uint8_t mode;        // SFRA_MODE_PLANT | SFRA_MODE_LOOP
} sfra_setup_t;

/* 每个频点只扫一遍（D19 单 pass）：
   inject() 边注入边累加 Inj，monitor() 用同一个 θ 累加 Y（PLANT 再累加 X） */
#define SFRA_MODE_PLANT 0
#define SFRA_MODE_LOOP  1

typedef struct {
    float *freq_vect;                   // ★ 固件写入实际频率 f_act（D7）
    float *a_c, *a_s;                   // Y 累加器原值（out）
    float *b_c, *b_s;                   // PLANT: X(in) | LOOP: Inj 累加器原值
} sfra_result_t;
/* v2：不再存 mag/phase。每个频点 4 个 float + 1 个 freq，由 PC 计算并解释 */

typedef struct {
    sfra_setup_t    cfg;
    sfra_result_t   res;
    sfra_internal_t st;   // 状态机 + 6 个 int64 累加器 + theta_phase/step_phase
} sfra_t;
```

**状态机（非阻塞，libsfra 同款结构）**

```
IDLE ──start()──> SETTLE ──settle 递减到 0──> COLLECT ──采满 data_count──> NEXT
                     ↑                                                       │
                     └──────────── 还有频点：装下一个频点 ←─────────────────┘
                                                                              │
                                                    最后一个频点 ──> DONE <───┘
```

| 状态 | 谁推进 | 做什么 |
|---|---|---|
| `SETTLE` | `inject()` 每周期减 1 | 不累加；减到 0 时改 `COLLECT`（`background_task` 兜底翻译） |
| `COLLECT` | 两个函数各干各的 | `inject()` 累加 Inj（仅 LOOP）；`monitor()` 累加 Y（+X）；采满即停 |
| `NEXT` | `background_task` | 写 `res`、装下一频点、清累加器、复位 settle |
| `DONE` | `background_task` | 等上位机取数 |

**扫频总耗时**
$$T = \sum_k \frac{N_{cyc,k}}{f_{act,k}}$$
PLANT 与 LOOP **相同**。v2 曾写"LOOP 是 PLANT 的 2 倍"，那是"分两 pass"的旧设计；D19 改成单 pass 后这个 2 倍因子必须去掉，否则上位机进度条会走一半就停在 100%。

**θ 与计数的归属（实现必须照此，否则累加器对不齐）**

| 量 | 谁改 | 说明 |
|---|---|---|
| `theta_phase` | **`sfra_advance()` 每周期加 `step_phase`** | `inject()` / `monitor()` 都只读。**必须在 `monitor()` 之后调用**（坑 A1） |
| `step_phase` | `background_task`，换频点时写 | Q32 归一化相位增量 = `rad/2π × 2^32`；相位本身跨频点**不重置**（坑 A2） |
| `settle_left` | `inject()` 递减 | inject 是每周期唯一必经点，靠它计时 |
| `collected` | `monitor()` 递增 | 到 `data_count` 就停手；`inject()` 判同一个上限（坑 A3 + A15） |
| 6 个累加器 | `monitor()` 累加 Y/X；`inject()` 累加 Inj | 全是 int64 Q42（见 1.9 节） |

> **没有 `channel` 了**：v2 用 `channel` 在 pass 之间切换"这一遍采谁"，还要靠 `spin` 握手防竞态。单 pass 之后这个状态量整个消失——少一个状态量就少一类竞态，是 D19 顺带赚到的。

**`b_c/b_s` 的语义（别实现错）**

- PLANT：`monitor()` 累加 `Y(out)` 与 `X(in)`；`inject()` 不累加。收尾时 `res.b = X`，PC 算 `H = Y/X`。
- LOOP：`monitor()` 只累加 `Y(out)`；`inject()` 在**同一周期**累加 `Inj += inj·cosθ / inj·sinθ`。收尾时 `res.b = Inj`，PC 算 `GH = Y/(Inj−Y)`。

两条路径都要求 `Y` 与 `b` 的采样点数**严格相同**——所以 `inject()` 里那句 `s->collected < s->data_count` 判断不是可选的（坑 A15：少了它 Inj 会多积 2~5 点，`Inj−Y` 的相位偏 0.08°）。

**ISR 开销（S2 实测，非估算）**

| 项 | M4F @168MHz | M0+ @48MHz |
|---|---|---|
| `sfra_inject` | 101 条指令 | 161 / 164 条（float / Q15） |
| `sfra_monitor` | 103 条指令 | 167 / 174 条 |
| `sfra_advance` | 5 条指令 | 同左 |
| 热路径软浮点调用 | **0** | **0** |
| PC 计时（x86-64） | 5.8 ns / 7.0 ns per frame | — |

指令数用 `arm-none-eabi-objdump` 数出来的，是**静态指令条数**，不等于周期数（还有流水线、访存、分支预测）。真实周期数必须在目标板上用 `DWT->CYCCNT` 量——这是 S4 的 DoD。PC 的 ns/frame 只说明"算法本身要多少次乘加"，不能直接当 MCU 开销用。

### 2.2.2 `sfra_proto.c/h` —— 串口协议栈

- 收：字节进环形缓冲（UART 中断/DMA 填），主循环 `sfra_proto_poll()` 解析。
- 发：float32 原样小端（PC 端 `struct.unpack('<f')`）。
- **DATA 帧载荷 = 累加器原值**（v2，00 文档 D6）：每频点 `{f_act, a_c, a_s, b_c, b_s}` 共 5×f32 = **20 B**。
- 大数组分帧：DATA 载荷头是 `start_idx(u16) + count(u8)` = 3 B，之后跟 `count` 个点。
  LEN 字段只有 1 字节（上限 254 B payload），所以**一帧最多 7 点 = 3 + 7×20 = 143 B**。
  带 `start_idx` 序号，丢帧只重发该段。
  > 早期设计按 u16 LEN 写过"每帧 8 点 = 160 B"，改为 1 字节 LEN 后必须收到 7 点。
  > 这个数字在 `comm/protocol.py` 的 `MAX_POINTS_PER_FRAME` 与 `controller.py` 的
  > `FETCH_CHUNK` 两处硬绑定，改一边必须改另一边。
- 不阻塞：TX 空间不足则挂起，下次 poll 重试，绝不发半帧。

### 2.2.3 `sfra_port.h` —— 适配层（唯一要用户填）

```c
/* 四个必需函数：只有声明，库里没有定义 */
void    sfra_port_uart_write(const uint8_t *buf, uint16_t len);
int16_t sfra_port_uart_read_byte(void);   // 无数据返回 -1
void    sfra_port_enter_critical(void);
void    sfra_port_exit_critical(void);

/* 两个可选的弱符号：库里有默认实现（返回空条件 / 不支持），
   用户在应用里定义同名函数即可覆盖，不需要改库 */
int sfra_proto_get_conditions(float out[8]);      // Vin,Vout,Iout,T1,T2,…
int sfra_proto_set_coeff(uint8_t order, const float *b);
```

> **旧版文档里的 `sfra_port_get_vin/get_vout/get_iout` 已删除。**
> 那三个函数与 `sfra_proto_get_conditions(float out[8])` 表达的是同一件事，
> 两套接口会逼用户维护两条数据通路，而且"读一个电压"和"读一组测试条件"
> 在协议上本来就是同一个 GET_CONDITIONS 命令。统一收编到 `get_conditions`。

> **重要事实：`sfra_core.c` 与 `sfra_proto.c` 不调用任何 `sfra_port_*` 函数。**
> 这是"零 HAL 依赖"设计原则的直接结果——库的调用链上没有一处需要发给硬件。
> 所以：**不实现这四个函数，库照样编译、链接、通过全部单元测试**。
> 它们只在 `examples/` 的参考集成里被调用，删掉实现不会有链接错误来提醒你。
> 上板时请照 §2.2.3 末尾的自检清单逐条勾，不要指望编译器报错。

**用户在应用里要做的全部工作（两种扫频共用一份 ISR 代码）：**

```c
/* ① 控制 ISR 内 —— 三行的顺序不能变 */
void PWM_ISR(void) {
    sfra_signal_t inj = sfra_inject(&sfra);     // ① 产正弦 + 计时 + 累加 Inj（不推进 θ）

    /* 注入按模式落到不同位置：两者都算，由 exec 二选一（不用 if 分支） */
    float r    = ref_dc  + inj;                 // LOOP：注到参考
    float x    = duty_dc + inj;                 // PLANT：注到执行量（开环）
    float u    = PI_Run(&pi, r, vo);            // 补偿器（原有代码，PLANT 时输出被丢弃）
    float exec = (sfra.cfg.mode == SFRA_MODE_PLANT) ? x : u;

    sfra_monitor(&sfra, exec, vo);              // ② in 按 mode 自动取舍
    sfra_advance(&sfra);                        // ③ 必须在 monitor 之后
    TIM1->CCR1 = (uint32_t)(exec * PERIOD);
}

/* ② 主循环 —— 两个都要调，顺序无所谓 */
while (1) {
    sfra_proto_poll(&sfra);      // 收命令、发数据
    sfra_background_task(&sfra, &res); // 推进状态机、换频点、写结果
}
```

**这条 ISR 里必须遵守的 5 条**（写进 SOP 与代码注释）：
1. `sfra_inject()`、`sfra_monitor()`、`sfra_advance()` **每周期各调一次**，顺序 `inject → monitor → advance`；
2. `advance()` **绝不能**挪到 monitor 之前，也绝不能省——它是 θ 唯一的推进点（坑 A1：挪前一位，整条曲线偏 `360/data_count` 度，高频能到 −30°）；
3. 注入量必须**在限幅之前**叠加（`exec` 是限幅前的原始值，限幅后的值不具线性度）；
4. `sfra_monitor()` 的 `out` 必须是**与注入同拍采到的反馈**（ADC 在 ISR 开头读取，不要用上周期缓存）；
5. ISR 里**不要**调用 `sfra_background_task()` 或任何协议函数。

`bode_data.py` 是 v2 新的关键点：MCU 上报的 `(a_c, a_s, b_c, b_s)` 按模式解释为
- PLANT：`H = (a_c − j·a_s)/(b_c − j·b_s)`
- LOOP：`GH = (a_c − j·a_s)/((b_c − a_c) + j·(a_s − b_s))`，即 `Y/(Inj − Y)`

**相位符号约定只写在这里一次**，配 L0 仿真测试锁死。

**线程模型**：主线程 + QSerialPort 事件驱动 + **200 ms** QTimer 轮询状态机。不做多线程——
921600 下全部数据 < 3 KB，瓶颈是扫频物理耗时，PC 只是等。

> 轮询周期不能再放宽：固件 `SFRA_PROTO_TIMEOUT_MS = 500`，MCU 连续 500 ms 收不到有效帧
> 就自动 ABORT。`POLL_MS = 200` 留了 2.5 倍裕量；取 400 ms 已在断线边缘，
> 一次 USB 枚举抖动就会让整轮扫频作废。

## 2.5 存储与命名

- 每次扫频一个"测试会话"：`{时间戳}_{拓扑}_{Vin}V_{Vout}V_{Iout}A_{fsw}`，内含
  - `plant.csv` / `loop.csv`（TI 兼容列名：`Frequency(Hz), Magnitude(dB), Phase(deg)`）
  - `raw.npz`：累加器原值（a_c/a_s/b_c/b_s/f_act）——**原始数据可复算**，算错能重算不用重扫
  - `meta.json`：测试条件 + 标定系数（pu 元数据）+ 补偿器系数 + 固件版本 + 扫频设置
  - `bode.png`
- 默认目录 `%USERPROFILE%/Documents/SFRA Studio/`。
