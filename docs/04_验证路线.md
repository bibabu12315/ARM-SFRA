# 04 验证路线（v3 定版 · 可开发基线）

> **本文回答：验证体系怎么分层。** L0/L1/L2/L3 各证明什么、每层 gate 判什么、
> L 层与 S 阶段怎么对应、以及三个运行时护栏。
>
> **本文不是"验收方法"**——验收时拿什么当基准、每关怎么判生死，看
> [`10_验收路线.md`](10_验收路线.md)。两者是**体系设计**与**验收方法论**的关系，
> 不是新旧版本，都有效。10 号文档的 §2「三条曲线」是本文 L3 那条
> "与模型比"判据的完整展开。
>
> 找不到该读哪篇 → [`README.md`](README.md)。

> 原则：**每一层都能独立证明自己是对的，出错时能立刻定位到哪一层。**
> SFRA 最危险的错误是"数值看起来合理但相位反了"这类**静默错误**，只能靠分层比对抓出来。
> v2 变更：L0 增加 GH 公式与相位符号的专项验证、L3 模型加入 ZOH/延迟、护栏 1 具体化为预扫规则、删里程碑表（与 4.1 重复）。

## 4.1 四层验证（每层是 gate，不通过不进下一层）

```
L0  纯 Python 仿真       ── 算法本身对不对？（对齐理论公式）
     │  通过条件：Plant/GH/PM/GM/fc/相位符号 与解析解误差 < 1.5 dB / 3°（Normal 档）
     ▼
L1  C 库在 PC 上跑       ── C 实现和 Python 实现是不是同一个东西？
     │  通过条件：同一激励，累加器原值逐位一致
     ▼
L2  MCU 内部一阶低通      ── 定点/浮点在目标 MCU 上对不对？ISR 开销多少？
     │  通过条件：与理论 Bode 误差 < 1 dB / 3°（filter_rc 替代功率级）
     ▼
L3  真实功率级            ── 接真 Buck，与含延迟的模型/阶跃响应交叉验证
        通过条件：Plant 与模型趋势一致；改 KP/KI 后 GH 的 fc 随之移动
```

### 4.1.1 L 层与 S 阶段怎么对应（两套编号，别混）

**L 层 = 验证深度**（"证明什么"），**S 阶段 = 实施顺序**（"先写哪个文件"）。
一个 S 阶段可能横跨两层，一层也可能被多个阶段共同验证。

| L 层 | 含义 | 对应 S 阶段 | 跑法 |
|---|---|---|---|
| **L0** | 纯 Python 仿真 vs 解析解 | **S1** | `pytest`（默认） |
| **L1** | C 库在 PC 上 vs Python 逐位比对 | **S2** | `pytest -m crosscheck` |
| **L2** | MCU 内部一阶低通（上真板） | **S6a** | 上板，人工 + 示波器 |
| **L3** | 真实功率级 | **S6b** | 上板，人工 + 模型对照 |

**S3、S4、S5 不属于任何 L 层**——它们验证的是"接线对不对"，不是"数值对不对"：

| S 阶段 | 验证对象 | 对应测试 |
|---|---|---|
| **S3** 串口回环 + 协议栈 | 帧编解码、CRC、分帧、状态机 | `pytest -m e2e`（`test_e2e_loop.py`） |
| **S4** 上位机联调 | 界面 ↔ 链路的会话时序、续传、中止 | `pytest -m e2e`（`test_link_controller.py`） |
| **S5** 上位机界面 | 布局、绘图、PM/GM、导出 | `pytest`（`test_export.py`）+ 人工看 |

> **历史坑**：旧版 00 文档把 S3 标成"（L2）"、S4 标成"（L2）"，两处都错了——
> L2 必须在**真 MCU** 上跑，而 S3/S4 全程在 PC 上。现已统一：
> **L2/L3 只属于 S6a/S6b**（见 00 文档 §0.5.4）。

## 4.2 L0：纯 Python 仿真（第一个可运行的东西）

**为什么先做**：整个上位机（界面、绘图、PM/GM、CSV 导出）在**没有 MCU 的情况下完整跑通**，且被测对象"答案已知"。

**实现**：
- `sim/sfra_sim.py` —— 逐行移植 `libsfra.c`：整周期取整、θ 递推、6 个累加器（Y/X/Inj 各 2）、**不含 atan2**（与 C 版一致，只出累加器原值）。
- `model/bode_data.py` —— 按 01 文档 1.2 的约定 `Z = S_c − j·S_s` 由累加器算 mag/phase。**相位约定唯一实现处，测试锁死。**
- `sim/plants.py` —— 被测对象：

| 对象 | 传递函数 | 验证点 | 理论值 |
|---|---|---|---|
| 一阶低通 | $\frac{1}{1+s/\omega_c}$ | 相位符号、Plant 通路 | fc 处 −3 dB / −45° |
| RC 数字滤波（libsfra `filter_rc`） | 双线性离散 RC | 离散化、C/Python 同源性 | 同解析 |
| 二阶 LC（Buck 功率级） | $\frac{1}{1+s/(Q\omega_0)+s^2/\omega_0^2}$ | 谐振峰、−180° 陡降 | 谐振处 −90° |
| 数字 PI + LC 闭环 | $T = G \cdot H$ | **GH 通路（v2 新）** | scipy 解析 PM/GM |

**通过条件（pytest）**：**L0 一律用 Normal 档（≈100 周期/点）验证**——Fast 档精度只有 ~1 dB / 5°，不够锁相位。
```python
def test_plant_vs_theory():      # 开环 Plant 通路
    assert abs(mag_err_dB) < 1.5 and abs(phase_err_deg) < 3.0

def test_loopgain_vs_theory():   # 闭环 Ref 注入 → GH = Y/(Inj−Y)
    # 理论 T = G·H 由 scipy 算；GH 实测由"闭环仿真 + Inj 累加"算
    assert abs(pm_meas - pm_theory) < 2.0        # deg
    assert abs(gm_meas - gm_theory) < 1.5        # dB
    assert abs(fc_meas/fc_theory - 1) < 0.05

def test_phase_sign():           # 相位符号专项（v1 的教训）
    # 一阶低通相位必须 0 → −90°；若 +90° 说明复数约定实现反了
    assert all(ph <= 0 for ph in phase_curve_of_lowpass)
```

> `test_phase_sign` 是 v2 专门加的：v1 文档的相位公式就曾在符号上自相矛盾。这个错误一旦带进固件，表现为"PM 很高其实很危险"，必须用测试在源头锁死。

**L0 的额外价值**：离线验证注入幅值敏感度——同一对象用 A 和 10A 注入，曲线差异即非线性敏感度。

## 4.3 L1：C 库在 PC 上交叉验证

**做法**：`sfra_core.c` 用 gcc 编译成 PC 可执行程序，喂 Python 生成的同一组激励，**比对累加器原值**（不是 mag/phase——幅相只在 PC 算，MCU/C 库只产原值）。

**要抓的分歧**：整周期取整的 `ceil` 行为、θ 用 float 弧度还是 Q32 定点、定点缩放因子、Inj 累加器是否在 SETTLE 期间也被累加（不应）、cos/sin 有没有对调。

**通过条件**：浮点路径 < 0.01 dB / 0.05°（折算后）；定点路径 < 0.05 dB / 0.3°。

**实测结果（2026-11-23，S2 完成）**：10 个用例全绿。浮点最差 0.0086 dB / 0.0277°，定点最差 0.0196 dB / 0.0499°。详见 00 文档 §0.5.6。

**两处必须防的"假通过"**：

1. **Python 端按 double 算、C 端按 float32 算**。这类差异不是算法错，但会淹没真正的 bug。做法：`gen_script` / `run_py` 全部把中间量压回 float32 再算，写文本统一 `float(np.float32(x)):.9g`。
2. **分母为 0 时跳过**。定点路径首次跑出 `0.0000 dB / 0.0000°` 的 PASS，实际是 dump 把 float 塞进 `int16` 参数被截成 0/1，累加器全空，而 `compare()` 在 `|S|≤0` 时 `continue` 了。现在 `compare()` 统计跳过数，**有任何一个零分量直接判失败**。

**跑法**：
```bash
python tools/cross_check.py        # 全表输出（约 70s）
pytest -m crosscheck -v            # 11 个用例（S2 的 10 个 + sfra_port.h 编译断言 1 个）
```

> `test_port_header.py` 里那条 `test_port_layer_compiles_with_library` 编的是**正向**用例：
> 它只证明 "port 头 + port 实现 + 库能一起编译"。它**不能**证明"缺 port 实现会链接失败"——
> 因为 `sfra_core.c`/`sfra_proto.c` 根本不调用任何 port 函数（零 HAL 依赖是设计原则）。
> 这条护栏已经换成"文档里必须明确写下这个事实"，由
> `test_port_header_documents_no_link_enforcement` 锁住。
>
> **MinGW 环境坑**：编译测试必须把 `tools/toolchain/w64/mingw64/bin` 加进 `PATH`。
> `gcc.exe` 只是驱动器，真正干活的 `cc1.exe` 需要同目录下的
> `libgmp-10.dll` / `libmpc-3.dll` / `libisl-23.dll`，而 Windows 没有 rpath。
> 找不到 DLL 时 `cc1` **直接 exit 127 且 stderr 一个字都不打印**——
> 表现为"测试失败但没有任何错误信息"，极难排查。

**附带**：PC 上跑 100 万次 inject+advance+monitor 计时（浮点 5.8 ns、定点 7.0 ns per frame），已回写 01 文档 1.9 与 02 文档 2.2.1。注意这只能当"算法本身要多少次乘加"的参考——**真实周期数在 S4 用 `DWT->CYCCNT` 量**。

## 4.4 L2：MCU 内部一阶低通（不接功率级）

用 libsfra 的 `filter_rc.h` 替代功率级（照抄 libsfra readme 的自测用法）：

```c
const float dc_gain = 100.0f;
void control_law_run(void) {
    sfra_signal_t inj = sfra_inject(&sfra);              // 注在"参考"（LOOP 模式）
    float x = 1.0f + inj;
    float y = dc_gain * vFilterRCRun(&test_filter, x);   // 一阶低通当被控对象
    sfra_monitor(&sfra, 0, y);                           // in 被忽略
    sfra_advance(&sfra);                                 // 别忘了这一行
}
```

**这一层验证四件事**：
1. 定点/浮点在目标芯片上数值不溢出（int64 最坏情况）；
2. ISR 开销可接受（GPIO 翻转 + 示波器实测 inject+monitor 时间，最硬的证据）；
3. **相位符号正确**（一阶低通必须 0 → −90°，看到 +90° 就是约定实现反了）；
4. 扫频时长与上位机按 f_act 的预估一致。

**通过条件**：Bode 与理论 < 1 dB / 3°；ISR 附加时间 < ISR 周期 10%（M4F）/ 20%（M0+ 定点）。

> **这一步已有可执行交付件**（等真板）：
> `firmware/examples/stm32/sfra_selftest_stm32.c`（自测固件）、
> `tools/selftest_s6a.py`（验证脚本）、`docs/06_S6a上板接入指南.md`（步骤）。
>
> **判据要分两段**（06 文档 §6.4 有完整解释）：
> 固件用 Tustin 离散化，它在 `f_s/5` 处比连续域解析解低 **1.26 dB**——
> 这是双线性变换的频率轴翘曲，不是 bug。所以：
> - 全频段跟**离散域解析解**比，0.5 dB / 1.5°（真 bug 判据）
> - 低频段（f ≤ 10·fc）跟**连续域解析解**比，1 dB / 3°（物理对象）
>
> 只跟连续域比会让正确固件被判 FAIL；只跟离散域比则看不到离散化偏离多远。

## 4.5 L3：真实功率级（Buck / Boost / Buck-Boost）

**Step 1 · 扫 Plant（开环）**
- 环断开，占空比手动给到标称工作点（Vin=24V, Vout=12V → D≈0.5）；确认 OVP/OCP 有效、电子负载能吸收输出；
- 先**预扫**（D16）：Fast 档、0.5% pu，读出谐振峰增益 → 反推正式扫频幅值上限；
- 期望形状：Buck 的 H 低频增益对应 Vin（pu 归一化后为常数）、LC 谐振处有含 ESR 的峰、之后 −40 dB/dec。

| 现象 | 可能原因 |
|---|---|
| 低频增益不符合换算值 | in 取错（取了扰动而非叠加后执行量）/ pu 归一化不一致 |
| 无谐振峰或峰太尖 | 负载/寄生；或注入幅值把系统推进 DCM |
| 高频段相位异常超前 | in 取在 PWM 之后（ZOH 被排除） |
| 低频增益随频率漂 | 整周期取整没做对（泄漏） |

**Step 2 · 扫 Loop Gain（闭环）**
- 闭环运行，补偿器用你已凑好的 KP/KI；
- 扫频期间**临时放宽补偿器输出限幅、禁用 anti-windup 复位**（限幅是非线性，会让 Bode"看着好但是假的"）；
- 期望：低频高增益（积分作用）、−20 dB/dec 穿越 0 dB，PM 与你阶跃测试观察到的稳定程度一致。

**Step 3 · 交叉验证（"真实性"的最终判据）**
1. **与模型比（必须含数字延迟）**：模型 = LC（L、C、ESR）× ZOH（$e^{-sT_s/2}$）× 一拍计算延迟（$z^{-1}$）。**不建延迟项，高频段实测必然比模型"差"，会被误判成算法错**——这是数字控制 Bode 最经典的坑。建对之后，误差应 < 3 dB / 5°；
2. **与阶跃响应比**：超调量 ↔ PM 经验关系，核对量级；
3. **改参数验证因果关系**：KI 减半 → 低频增益 −6 dB；KP 翻倍 → fc 上升、PM 下降。方向必须如预测，这是最强证据；
4. **双幅值校验**：A 与 2A 各扫一次，应重合（1 dB/3°）；不重合 → 非线性（靠近 DCM、饱和或限幅未放宽）。

**Step 4 · 记录基线**
- Vin/Vout/Iout/T/补偿器系数/pu 标定系数全部进 `meta.json`，作为"健康基线"；同机复测偏离 >3 dB 查硬件（电容老化、电感饱和、驱动退化）——TI 手册的"周期性健康诊断"用途。

## 4.6 三个护栏（v2 具体化）

**护栏 1 · 注入幅值安全（预扫反推 + 逐点监测）**
- 预扫：Fast 档、0.5% pu 快扫 Plant，读峰值增益 $G_{pk}$；
- 正式扫频幅值上限 = 允许扰动量 / $G_{pk}$，且不超过 **0.02 pu**（全链路 pu 量纲，D15；即 ADC 满量程的 2%）；
- 扫频中 `sfra_monitor` 检测 **`|out|` > 0.95 pu** 或占空比触及 [Dmin, Dmax] → 置饱和标志 → 上位机自动降 50% 重扫该点；连续 3 次降档仍饱和 → 终止扫频。

**护栏 2 · ABORT 立即生效**
- 上位机「停止」、串口掉线、MCU 端 500 ms 无有效帧，三个来源都触发 `sfra_abort()`：置 `amplitude=0`，`inject()` 下个 ISR 即返回 0。**不能只依赖上位机**。

**护栏 3 · 扫频中冻结被测系统**
- `RUN` 状态下"下发系数"按钮置灰（改系数 = 前后半段不是同一个系统）；
- 同理禁止改负载/输入电压设定；改任何东西都先 ABORT 再重来。
