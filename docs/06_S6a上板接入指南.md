# 06 S6a 上板接入指南（SOP 第 3 章主体）

> **本文是 SOP 第 3 章的底稿**：从"拿到一块空板子"到"扫出一条与解析解吻合的 Bode 曲线"，  
> 一步一步、每步都有可验证的通过标志。
>
> 跑完本文，你得到的不是"感觉能用了"，而是**三份硬证据**：  
> ① 逐点误差表（Bode 与解析解对比）② ISR 周期数实测 ③ 符号正确性证明。
>
> 前置：S1~S5 已完成（代码在 `src/` 与 `firmware/`），上位机能跑通假 MCU。  
> 本文对应 00 文档 §0.5.4 的 **S6a（L2 gate）**。

---

## 6.0 先搞清楚：S6a 验的是什么、不验什么

|          | 内容                                                                             |
| -------- | ------------------------------------------------------------------------------ |
| **验**    | 定点/浮点在**目标芯片**上不溢出；ISR 附加耗时**实测**可接受；相位符号在真机上仍正确；整条链路（UART→协议→扫频→回传→出图）在真硬件上跑通 |
| **不验**   | 功率级的 Bode 是否"像样"（那是 S6b）；补偿器设计得好不好；抗扰                                          |
| **被测对象** | 一个**软件一阶低通**（`filter_rc` 等价物），不是功率级                                            |
| **为什么**  | 一阶低通有闭式解，错了立刻能看出来。用功率级做首测，出问题时你无法区分"算法错"还是"接线错"                                |

> **别跳过这一步直接接功率级。** 功率级上如果相位反了，你看到的曲线依然"平滑合理"，  
> 很容易花几天怀疑电容和电感。S6a 用已知答案把算法问题一次性钉死。

## 6.1 硬件准备

| 项       | 要求                  | 说明                                     |
| ------- | ------------------- | -------------------------------------- |
| MCU     | Cortex-M0+/M3/M4/M7 | M0+ 无 DWT，只能用 GPIO 计时（见 6.5）           |
| UART    | 任意一路，**支持 921600**  | 至少要能稳定跑到 460800，否则降到 115200 并调大 ACK 预算 |
| USB-TTL | CH340/CP2102/FT232  | 921600 下劣质线会丢字节                        |
| 调试口     | SWD                 | 用来读 `DWT->CYCCNT` 或打断点                 |
| 示波器     | 可选，但**强烈建议**        | GPIO 翻转法测 ISR 占用是最硬的证据                 |

**接线**：`MCU_TX → USB-TTL_RX`、`MCU_RX → USB-TTL_TX`、`GND 共地`。  
**先只接这三根**，不要顺手接功率级——S6a 全程不需要功率级。

## 6.2 四步移植（只有 4 处要改）

把这三个文件加进工程：

```
firmware/sfra_src/sfra_core.c      算法 + 状态机（零依赖，不用改）
firmware/sfra_src/sfra_proto.c     协议层（零依赖，不用改）
firmware/examples/stm32/sfra_selftest_stm32.c   自测主程序（改 4 处）
```

头文件路径加 `firmware/sfra_inc/`。

### ① `sfra_port_uart_write()` —— 发送

```c
void sfra_port_uart_write(const uint8_t *buf, uint16_t len)
{
    HAL_UART_Transmit(&huart2, (uint8_t *)buf, len, 10);
}
```

- **必须发全**。用 DMA 时，`sfra_proto_tx_done()` 要等 DMA 完成中断里再调，  
  否则下一帧会覆盖正在发送的缓冲。
- 一帧最多 149 B，921600 下约 1.6 ms 阻塞——能接受。
- **不要在里面 `printf`**，会把二进制帧和文本混在一起。

### ② `sfra_port_uart_read_byte()` —— 接收

```c
int16_t sfra_port_uart_read_byte(void)
{
    return -1;          /* 字节走中断，主循环不用轮询 */
}
```

**推荐直接返回 −1**：字节由 UART RX 中断塞进协议层（见 ④）。  
这样主循环不会卡在等字符，状态机推进才不会被阻塞。

### ③ `sfra_port_enter/exit_critical()` —— 临界区

```c
static uint32_t g_primask;

void sfra_port_enter_critical(void)
{
    g_primask = __get_PRIMASK();
    __disable_irq();
}

void sfra_port_exit_critical(void)
{
    __set_PRIMASK(g_primask);       /* 必须恢复，不是无条件 __enable_irq() */
}
```

> **为什么必须保存/恢复**：嵌套调用时无条件 `__enable_irq()` 会提前开中断，  
> 保护就失效了。这个 bug 表现为"偶发数据错乱"，极难复现。

### ④ UART RX 中断

```c
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART2) {
        uint8_t b = rx_byte;
        sfra_proto_rx(&g_proto, &b, 1);      /* 或 sfra_selftest_uart_rx_isr(&b,1) */
        HAL_UART_Receive_IT(huart, &rx_byte, 1);
    }
}
```

**中断里只做这一件事**，绝不解析协议、绝不发数据。

### 主循环（三行，一个都不能少）

```c
while (1) {
    sfra_selftest_loop();        /* 内部含：收字节 → poll → 发应答 → background_task */
}
```

或自己展开（把 `sfra_selftest_loop()` 换成）：

```c
while (1) {
    sfra_proto_poll(&proto, &sfra, &res, now_ms());   /* ① 解析命令、组应答 */
    if (proto.tx_len) {                                /* ② 把应答倒出去 */
        sfra_port_uart_write(proto.tx_buf, proto.tx_len);
        sfra_proto_tx_done(&proto);
    }
    sfra_background_task(&sfra, &res);                 /* ③ 推进状态机 */
}
```

> ⚠️ **`sfra_background_task()` 必须无条件调用**。写成 `if (sfra_is_running())`  
> 会导致状态机卡在 NEXT（COLLECT 采满后 `is_running` 立刻变假）。  
> 这个坑在 S3 踩过，见 00 文档 §0.5.7。

## 6.3 第一次上电：先确认"能通"再谈别的

**不要一上来就扫频。** 按下面顺序，每步确认后再进下一步。

| 步 | 动作                                                        | 通过标志                       | 不通先查                                    |
| - | --------------------------------------------------------- | -------------------------- | --------------------------------------- |
| 1 | 烧录，串口接 PC，跑 `python -m serial.tools.miniterm COM7 921600` | 无乱码                        | 波特率、时钟配置                                |
| 2 | 上位机连接                                                     | 顶栏出现固件版本、`f_s`             | `sfra_port_uart_write` 是否发全             |
| 3 | 发 PING（上位机连接时自动发）                                         | 收到 PING_ACK                | `sfra_proto_rx` 是否在中断里被调                |
| 4 | 读 CAPS                                                    | 显示 `isr_freq`、最大点数         | `sfra_selftest_init()` 里 `def.isr_freq` |
| 5 | 读 CONDITIONS                                              | 显示你在 `get_conditions` 里填的值 | 弱符号是否被你的定义覆盖                            |

> **PING 不通的排查顺序**（90% 的问题在前两条）：
>
> 1. `sfra_port_uart_write` 真的被调用了？打个断点，别靠猜。
> 2. RX 中断里真的调了 `sfra_proto_rx`？很多人忘了在 `HAL_UART_RxCpltCallback` 里重新 arm。
> 3. `now_ms` 传的是不是 0？（传 0 = 关闭超时检查，调试时可用，正式必须开）

## 6.4 跑第一次扫频

```bash
python tools/selftest_s6a.py --port COM7 --fc 1000
```

`--fc` 必须与固件里 `SELFTEST_FC_HZ` 一致（默认 1000 Hz）。

脚本会打印逐点对比表和判定。**期望结果**（`fc = 1000 Hz`，`f_s = 100 kHz`）：

```
  f (Hz)   |H| (dB)   ∠H (°)    理论dB    理论°    ΔdB      Δ°
  ------------------------------------------------------------
    100.0     -0.04     -5.71     -0.04    -5.71   +0.00   -0.00
   1000.0     -3.01    -45.00     -3.01   -45.00   +0.00   -0.00
  10000.0    -20.05    -84.29    -20.04   -84.29   -0.01   -0.00
  20000.0    -41.26    -89.50    -40.00   -89.43   -1.26   -0.07
```

### 判据分两段，别混

| 判据              | 基准            | 范围        | 容差            |
| --------------- | ------------- | --------- | ------------- |
| **A**（真 bug 判据） | Tustin 离散域解析解 | 全频段       | 0.5 dB / 1.5° |
| **B**（物理对象）     | 连续域解析解        | f ≤ 10·fc | 1.0 dB / 3.0° |

> **为什么 20 kHz 处会有 −1.26 dB？**  
> 固件用 Tustin（双线性）离散化，它把整个 jω 轴压进单位圆内，频率轴被"翘曲"。  
> 一阶低通在 f_s/5 处的幅值偏差**恰好是 −1.26 dB**，相位偏差只有 0.08°。  
> **这是数学，不是 bug**——所以判据 A 拿离散域当基准，判定为 PASS。
>
> 如果只跟连续域比，一个完全正确的固件会被误判 FAIL。  
> 这个数字有测试锁住：`test_tustin_warp_at_nyquist_is_about_1p26db`。

## 6.5 测 ISR 开销（S6a 最硬的证据）

打开 `SFRA_SELFTEST_TIMING=1` 重新编译。

### 方法 A · DWT 周期计数器（M3/M4/M7）

```c
/* init 里做一次 */
CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
DWT->CYCCNT = 0;
```

然后在 ISR 首尾各读一次（`sfra_selftest_stm32.c` 已实现）：

```c
uint32_t t0 = DWT_CYCCNT_READ();
sfra_inject(&s); sfra_monitor(&s, x, y); sfra_advance(&s);
uint32_t dt = DWT_CYCCNT_READ() - t0;
```

算占用率：

```
占用率 = avg_cycles / (core_clock / isr_freq) × 100%
```

例：M4F @168 MHz、ISR 100 kHz → 1680 周期/ISR；若 avg = 130 → **7.7%**（DoD 要求 <10%）。

> ⚠️ **最常见的假通过**：忘记使能 CYCCNT，读数恒为 0，  
> 于是量出"零开销"。**第一步先确认计数在动**（读两次、中间空转几个循环，看是否变化）。

### 方法 B · GPIO + 示波器（任何 MCU，最硬的证据）

```c
GPIO_Set(DBG_PIN);      /* ISR 入口 */
... 三条 sfra 调用 ...
GPIO_Clear(DBG_PIN);    /* ISR 出口 */
```

量高电平宽度。优点是**包含中断延迟、流水线、访存**，谁也没法反驳；  
缺点是 GPIO 翻转本身有 2~5 周期开销。

### DoD

| 内核      | 附加时间占 ISR 周期 |
| ------- | ------------ |
| M4F     | < 10%        |
| M0+（定点） | < 20%        |

> 参考值（S2 静态指令数，非实测）：`sfra_inject` 101 条（M4F）/ 161 条（M0+ float）；  
> `sfra_monitor` 103 / 167。**这些不是周期数**，真实值必须按上面方法量。

## 6.6 四条常见失败与原因

| 现象                    | 原因                 | 查哪里                                                                   |
| --------------------- | ------------------ | --------------------------------------------------------------------- |
| 相位是 **+90°**（不是 −90°） | 复数约定实现反了           | **只在** `src/app/model/bode_data.py` 的 `Z = S_c − j·S_s`（D18）。全项目只该有一处 |
| 低频对、高频偏               | 整周期取整或 θ 递推有误      | 高频每周期点数少，取整误差被放大最快                                                    |
| 幅值整体差一个常数             | pu 归一化不一致（D15）     | `x` 和 `y` 是否同一 pu 基准；`amplitude` 是否 0.01                              |
| 曲线每次都不一样              | settle 不够 / 幅值低于噪声 | 升精度档（Normal）、加大幅值到 0.02 pu                                            |

> **判据 A 通过、B 不通过**：说明固件与"离散域应当的输出"完全吻合，  
> 但离散化本身偏离物理对象较多——通常是 `fc` 取太高（接近 f_s/10）。  
> 把 `SELFTEST_FC_HZ` 降到 `f_s/100` 重测。

## 6.7 S6a 完成标志（逐条打勾，不许跳）

**功能**

- [ ] PING / CAPS / CONDITIONS 三项应答正常
- [ ] 扫频能跑到 DONE，点数与 `SweepConfig.n_points` 一致
- [ ] `tools/selftest_s6a.py` 输出 **S6a PASS**
- [ ] 判据 A（Tustin）：幅值 < 0.5 dB、相位 < 1.5°
- [ ] 判据 B（连续域，低频段）：幅值 < 1.0 dB、相位 < 3.0°
- [ ] 相位全程为负、单调，无正值
- [ ] fc 处 −3 dB / −45°（±1.5 dB / ±6°）
- [ ] 高频斜率 −18 ~ −22 dB/dec

**性能**

- [ ] `DWT->CYCCNT` 或 GPIO 实测 ISR 附加时间：M4F < 10%、M0+ < 20%
- [ ] 48 小时连续跑不溢出（定点路径重点看 int64 最坏情况）

**安全**

- [ ] 拔掉串口，MCU 在 500 ms 内自动 ABORT（注入归零）
- [ ] 上位机点"停止"，注入立刻归零（不是等扫完）
- [ ] 临界区嵌套时中断不会提前打开（用 `__get_PRIMASK` 保存/恢复）

**记录**

- [ ] `get_conditions()` 填了真实的 Vin/Vout/Iout/温度
- [ ] 把这条基线曲线存成 CSV，作为"健康基线"（S6b 的对照起点）

## 6.8 从 S6a 走向 S6b

S6a 通过后，**换被测对象**就是 S6b：

1. 把 `control_isr_tick()` 里的 `lp1_step()` 换成你真实的 PWM 更新；
2. 把计时钩子搬进你的 **PWM 定时器中断**（而不是软件模拟调用点）；
3. 断开功率级先跑 LOOP（闭环），确认曲线形状合理；
4. 按 04 文档 §4.5 走 Step 1~4（Plant → Loop → 模型交叉 → 基线）。

**S6a 已经替你排除了**：协议错、算法错、符号错、位数不足、开销不可接受。  
S6b 如果出问题，**只可能是功率级或接线**——这就是分层验证的价值。
