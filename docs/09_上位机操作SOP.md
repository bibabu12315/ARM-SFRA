# 09 · 上位机操作 SOP（逐控件说明）

> 面向：第一次用这个工具、或者"用了但不知道每个框在决定什么"的人。
>
> 对应版本：v1.1　　最后更新：2026-11-24
>
> 本文以**测量页（Tab 1）**为主，因为所有会改变测量结果的控件都在这里。
> 补偿器页（Tab 2）只在下文 §9 简单带过，细节见 05 文档。

---

## 0. 三句话概括

1. **左边是"怎么扫"，中间是"扫出来什么样"，右边是"结果可信吗"。**
2. 左边的每一个数字都会**改变测量本身**，改完不会自动重扫——必须按「开始扫频」。
3. 右边的 PM/GM 是**结论**，左边的参数是**前提**。前提不成立，结论就没有意义。

### 1.2 顶栏右侧那两个胶囊

| 胶囊 | 什么时候变 | 内容 |

### 1.3 按钮标签为什么这么短

界面上有几处按钮用的是**短名**而不是完整英文，把鼠标停在上面会显示全称：

| 你看到的 | 完整含义 | 为什么缩 |
|---|---|---|
| `快` / `标准` / `精细` | Fast / Normal / Precise（精度档） | 三个全称要 246px，侧栏只给 216px |
| `cond` | `conditions`（读被测对象参数） | `conditions` 单占 100px |

原因只有一条：**左栏固定 300px，而文字不能被截断**。这一条是硬约束——
用户明确要求"窗口放大缩小，按钮里的字也要看得见"，所以宁可缩短标签，
也不让文字被压掉一半。完整的英文名保留在 tooltip 里，鼠标悬停即见。

> **维护提示**：要加新按钮或改标签，先跑
> `.venv/Scripts/python.exe tools/_stress_resize.py`。它会扫
> 29 组窗口尺寸 × 系统字号，任何一处文字放不下都会报出来。
> 判据是 Qt 自己算的内容矩形，不依赖界面代码的假设，见 `docs/00` v4.6。

## 2. 扫频配置（左栏上半）

### 2.1 模式：Loop Gain / Plant

| 选项 | 量的对象 | 注入点 | 用在哪 |
|---|---|---|---|
| **Loop Gain** | 开环增益 `GH(s)` | 加在**参考值 r** 上（误差之前） | 判断环路稳不稳，算 PM/GM |
| **Plant** | 被控对象 `G(s)` = 输出/占空比 | 加在**执行量 u** 上（误差之后） | 判断功率级本身对不对 |

**为什么必须分开**：两者的分母不同。

- LOOP：`GH = Y / (Inj − Y)`，分母是"注入复振幅减反馈复振幅"
- PLANT：`G  = Y / U`，分母是"执行量复振幅"

注入点都在闭环里，但**量的通路不一样**。混着看会得到"PM 180°"这类怪值。

**实操建议**：先扫 Plant 确认功率级模型对得上（与本文 §8 的基准比），
再扫 Loop Gain 看裕度。顺序反了，Plant 有问题时会把责任错算到补偿器上。

**限制**：有些拓扑开环会失控，只能扫 Loop Gain：
LLC 轻载进 Burst、无桥 PFC 开环电流失控。见 05 文档 §5.4.2。

---

### 2.2 起点（Hz）

扫频的**第一个频点**。默认 100 Hz。

决定什么：

- 曲线左端从哪开始。设成 100 Hz，左边就什么都没有。
- 低频点很**费时间**：一个 100 Hz 周期就是 10 ms，Normal 档要积 10 个周期
  = 100 ms 一个点。设成 10 Hz 会慢十倍。
- 想验证"直流增益对不对"，起点要低到 `f ≪ f0`（一般 `f0/10` 以下）。

**常见错**：起点设 1 kHz，然后抱怨"低频段怎么是平的"——因为压根没扫。

---

### 2.3 终点（Hz）

扫频的**最后一个频点**。默认 20 000 Hz。

**会被自动截断**：固件和上位机都有一条硬上限 `f_s / 5`（实用 Nyquist 上限）。

| ISR 频率 | 上限 f_s/5 | 填 40 kHz 实际扫到 |
|---|---|---|
| 100 kHz | 20 kHz | 20 kHz（点数变少，框变橙色） |
| 200 kHz | 40 kHz | 40 kHz |
| 50 kHz | 10 kHz | 10 kHz |

**为什么是 f_s/5 而不是 f_s/2**：注入频率越接近采样率，每个周期内的
采样点越少。低于每周期 5 点时，DFT 的整周期取整误差、相位步进误差会
被急剧放大，幅值能凭空虚高十几 dB。这是实测结论，不是保守估计。

终点被截断时，「预计 N 点」会变成橙色，鼠标悬停能看到原值和新值。
**这时不要以为工具坏了**——它在保护你。

---

### 2.4 点数 / decade

**每十倍频程取几个频点**。默认 20。

这是**密度**，不是总数。总数由起点、终点、这个密度共同决定：

```
总点数 = floor( log10(终点/起点) × 点数每decade ) + 1
```

举例（起点 100 Hz）：

| 点数/decade | 相邻点倍数 | 100 Hz → 20 kHz 的点数 | 扫一遍约 |
|---|---|---|---|
| 10 | ×1.26 | 24 | 快，但谐振峰可能整个漏掉 |
| **20**（默认） | ×1.12 | **47** | 曲线平滑，够用 |
| 40 | ×1.06 | 93 | 谐振峰形状清楚，时间翻倍 |
| 80 | ×1.03 | 185 | 过度，逼近固件 256 点上限 |

**怎么选**：

- **只看 PM/GM** → 20 足够（穿越点附近有 3~4 个点就能插值）
- **要看清谐振峰的 Q** → 40 起（Q=5 时峰宽不到 1/5 decade，
  20 点/decade 只有 3~4 个点落在峰上，峰顶会被削平）
- **点数上限 256**：超过固件会回 `BAD_PARAM`，上位机在按「开始」前就拦住

**注意**：改这个数字**不改变总时长里的单点时长**，但会改变总点数，
所以总时长跟着变。左栏底部「预计 N 点 / 约 xx s」会实时更新。

---

### 2.5 精度：Fast / Normal / Precise

每个频点**积分多少个周期**。这直接决定：
① 测得多准 ② 扫得多慢 ③ 抗噪能力。

| 档位 | 每点周期数（大致） | 相对耗时 | 用在哪 |
|---|---|---|---|
| **Fast** | 8 周期（且至少 20 ms） | 1× | 快速看形状、演示、粗定位 |
| **Normal**（默认） | 10~100 周期（随频率升高） | ~10× | **验收口径**，所有判据都按这一档 |
| **Precise** | 200 周期 | ~20× | 低幅值、高噪声、要存档的基线 |

**为什么周期数随频率变**：高频一个周期只有几十微秒，
积 10 个周期只有几百点，统计上不够。所以 Normal 档在高频会自己加周期，
保证每点总采样点数够。这个逻辑在 `sim/sfra_sim.py::calc_cycles`，
PC 与固件共用同一份实现。

**注意 Fast 档的陷阱**：它保证"每点至少 20 ms"，低频时这会变成
只积 2 个周期，settle（换频静默）都不一定够。所以 Fast 档的曲线
**不能用来算 PM/GM**，只能看趋势。文档里所有精度判据都写明 Normal。

---

### 2.6 注入幅值（% pu）

**给系统灌多大的正弦扰动**，单位是标幺值（pu，1 pu = 满量程）。

默认 1.00 %pu，固件上限 0.25 pu（25 %）。

决定什么——这是**最需要权衡**的一个参数：

| 幅值太小 | 幅值太大 |
|---|---|
| ADC 量化噪声盖住信号 | 被测对象进入非线性/限幅 |
| 曲线毛刺、相位乱跳 | 增益被压缩，测出的 PM 偏大（假安全） |
| 判据"每周期采样点"正常但对不上解析解 | 饱和标志置位，右栏出橙色告警条 |

**怎么定**：

1. 先看右栏「曲线信息 → 注入幅值」下方是否提示"偏低"——
   判据是"注入峰值 ≥ 10 LSB"。低于 10 LSB，改大；
2. 扫完看有没有饱和告警条。有就改小重扫；
3. 两头都满足的那个值就是合适的。

**一个容易忽略的点**：加大幅值**不会**让曲线更平滑地"更准"。
它只是在"量化噪声"与"非线性"之间找平衡点。幅值调到 20 %pu
测出来的幅频曲线，高增益处已经开始压缩，反而更不真。

**「预扫」按钮就是解决这件事的**（见 §2.8）。

---

### 2.7 ISR 频率（kHz）

**MCU 的控制中断频率**。默认 100 kHz。

这个数字**不是**用来"配置"固件的——它是你**告诉上位机**固件在跑多少。
上位机用它做四件事：

1. **算实用上限**：`f_s / 5`，截断终点（§2.3）
2. **算整周期取整**：`data_count = ceil(f_s·cycles/f)`，决定每个点的采集窗
3. **算实际频率** `f_act`：横轴画的是 f_act，不是名义值
4. **算每周期采样点数**：`f_s/f`，低于 4 点标黄、低于 2 点剔除

**填错了会怎样**：

- 填成 2 倍（200k vs 实际 100k）→ 终点被允许到 40 kHz，实际每周期
  采样点只有一半，高频数据全是垃圾
- 填成一半 → 终点被过早截断，白白少扫一段

真链路模式下，握手时固件会上报 CAPS（含真实 ISR 频率），
上位机会**自动覆盖**这个框。所以真机路径下填错不致命，
但**仿真路径下必须自己填对**。

---

### 2.8 上限反推（预扫）

按钮文字「预扫」，右键提示"在谐振附近找峰值，自动下调注入幅值防止饱和"。

**它做什么**：

1. 用当前配置的一个**子区间**（谐振附近）粗扫几个点
2. 找峰值频率与峰值幅值
3. 按"峰值处不能顶到满量程"反推出一个更小的注入幅值
4. 把这个值填进「注入幅值」，并在状态栏提示

**什么时候用**：

- 不知道被测对象的谐振峰有多高（比如第一次接某个功率级）
- 上次扫出饱和告警，但不知道降多少才对

**什么时候不用**：已经知道合适的幅值，或者时间紧。它本身也要花十几秒。

## 3. 被测对象（左栏下半）

### 3.1 这个区域是干什么的

**只在仿真模式（无硬件）下有效。接到真 MCU 后，整块被忽略。**

仿真模式下，上位机需要知道"被控对象是什么"，才能自己算出一条曲线给你看。
这块就是让你描述那个"虚拟对象"。

| 控件 | 含义 |
|---|---|
| 仿真模型 | 二阶 LC（Buck 功率级）/ 一阶 RC（RC 低通） |
| 谐振 / 截止（Hz） | 二阶 LC 填 f0，一阶 RC 填 fc |
| 品质因数 Q | 只对二阶 LC 有效（Q = 0.5 临界阻尼，2 有凸峰） |
| Kp / Ki | 闭环模式下 PI 补偿器参数（离散并行式，Ki 单位 1/s） |

### 3.2 「为什么需要选模型？直接扫不就行了？」

这是个好问题，而且很多人的直觉是对的——**接真硬件时确实不需要选模型**。

区别在于**谁产生曲线**：

```
真链路模式：
    MCU 真的在注入正弦、真的在累加 DFT → 上报原始累加器
    上位机只负责  H = Y/X  然后画图
    → 不需要模型。模型在 MCU 外面（就是真实的功率级）

仿真模式：
    没有硬件。要有东西注入、要有东西响应、要有东西累加。
    上位机必须自己造一个"虚拟功率级"来当这个响应源
    → 必须告诉它这个虚拟对象是什么
```

所以"被测对象"这块本质是**仿真用的脚手架**，不是产品功能。

**为什么不做成"自动识别"**：识别需要激励-响应数据，而没有模型就
没法产生激励-响应——鸡生蛋。而且真链路下根本没这个需求。

**仿真模式的价值**：没板子的时候能跑通全流程、验证算法、做演示。
它的曲线**不能当验收依据**（除非你就是要验证仿真算法本身）。

### 3.3 一个容易误解的地方

仿真里的「二阶 LC」用的是**归一化形式**：

```
H(s) = 1 / (1 + s/(Q·ω0) + (s/ω0)²)        ← 直流增益 0 dB
```

而**真实 Buck 功率级**是：

```
G_vd(s) = Vin / (1 + s/(Q·ω0) + (s/ω0)²)   ← 直流增益 = Vin（12V → +21.6 dB）
```

两者形状完全相同，整体相差 Vin 倍。所以**仿真曲线不能直接和真机曲线
比绝对高度**，只能比形状。

要看"真实应该长什么样"，用 §8 的基准工具，加 `--vin 12`。

## 4. 动作区与进度（左栏底部）

### 4.1 预计 N 点 / 约 xx s

不是装饰。它回答"这次要等多久"。

- **N 点**来自 §2.4 的公式，并已扣除 f_s/5 截断
- **时间**按 **f_act**（实际频率）算，不是名义频率。低频段两者差
  能到 10%（周期数少、采集点数向上取整）
- 变橙色 = 终点被截断了

### 4.2 「开始扫频」

点下去会依次：

1. 用 `SweepConfig.validate()` 做一致性校验（与固件同源），
   有**硬错误**直接弹窗拦下，不会发出去
2. 有**软警告**（如"高频段每周期只有 3.5 点"）写进右栏告警，但继续
3. 下发配置 → 启动后端（仿真线程 / 真链路状态机）
4. 清空旧曲线、进度归零、按钮状态切换

### 4.3 「停止」

中止扫描。已经采到的点**保留**（可以做部分分析），但不会算 PM/GM
（因为可能缺穿越点）。

### 4.4 「导出」

扫完才可用。导出 CSV / JSON / Markdown，路径与格式见 02 文档 §2.5。

JSON 里保留了**原始累加器**（不只是幅相），所以算错了能离线重算，
不用重扫。这是刻意设计。

### 4.5 扫描进度条与它下面的三行读数

```
Loop Gain · 扫描中                    57%
[████████████░░░░░░░░░░░░░░░░]
f_act 5.42 kHz          12 样本/周期
```

| 元素 | 含义 |
|---|---|
| 左侧状态 | `模式 · 状态`：就绪 / 扫描中 / 完成 / 已中止 / 失败 |
| 右侧百分比 | `已完成点数 / 总点数` |
| f_act | **当前这一点的实际频率**（整周期取整后反算） |
| 样本/周期 | `f_s / f_act`。低于 4 标"偏低"，低于 2 的点会被剔除 |

**关于"进度条停在 57%"**：

这个数字本身是 `done/total`。停在某个值不动，说明**后端没有送来新的
完成点**，不是进度条算错了。可能的原因按概率排：

1. **该频点采集超时**（MCU 侧 settle 时间不够、ISR 被高优先级打断）
   → 固件状态机停在 `SFRA_ST_MEASURE`
2. **DATA 帧丢失**（串口丢字节、CRC 校验失败被丢）
   → 上位机在等 `start_idx == next_idx` 的那一帧，等不到就永远等
3. **`STATUS.freq_index` 语义误解**
   → 固件报的是"**正在采**的点索引"，不是"已完成数"；如果某个点的
   `freq_index` 不再推进，`available` 也就卡住
4. **真断了**（串口松动、MCU 复位）

**排查顺序**（v1.1 起右栏告警会给出具体频点）：

```
① 看右栏告警 → 是否已提示"第 N 点无响应"
② 看 f_act 是否还在变 → 变了说明 MCU 还在跑，只是慢
③ 看「样本/周期」→ 是否为 0 或异常大（说明 f_act 卡住了）
④ 拔插串口后重连，看是否能继续（续传机制见 03 文档 §3.6）
```

**一个反直觉的事实**：57% 这个具体数字不是固定的。它只是
"卡住的那一点 ÷ 总点数"。同一台设备换配置（比如点数/decade 从 40 改成 20），
卡在同一个物理频点时百分比就变了。

## 5. 中间图（幅频 / 相频）

### 5.1 两张图共享横轴

上面幅值（dB），下面相位（deg），**横轴联动**。鼠标在任一图上移动，
竖虚线同时穿过两张图，两张图的读数一起变。

### 5.2 交互

| 操作 | 效果 |
|---|---|
| 鼠标移动 | 显示该频率处的幅值/相位读数（底部一行） |
| 滚轮 | 缩放（以鼠标位置为中心） |
| 拖动 | 平移 |
| 双击 | 复位到全览 |

### 5.3 曲线颜色

| 颜色 | 含义 |
|---|---|
| 蓝色实线 | 实测（或仿真）曲线 |
| 紫色 | 预测曲线（来自补偿器页的模型计算） |
| 灰色虚线 | 0 dB / −90° / −180° 参考线 |
| 红色圆点 | 穿越点（扫完才标） |

### 5.4 低置信度的点不画

曲线只画**可信**的点。被判为不可信的有四类：

1. 每周期采样 < 2 点
2. 幅相为 NaN
3. LOOP 模式下 `|Inj − Y| / |Inj| < 0.05`（分母下溢，float32 精度不够）
4. LOOP 模式下相位相邻点跳变 > 75°

**所以"曲线右端突然没了"通常是正常的**——高频段 `|GH|` 很大，
`Inj − Y` 是两个几乎相等的数相减，float32 只剩 7 位有效数字，
相位已经不可信了。这不是 bug，是物理极限。

## 6. 右栏

### 6.1 稳定性判据

| 读数 | 含义 | 参考判据 |
|---|---|---|
| **相位裕度 PM** | 在 `|GH| = 0 dB` 处，相位离 −180° 还有多少 | 数字电源常用 45°~60° |
| **增益裕度 GM** | 在相位 = −180° 处，增益离 0 dB 还有多少 | 常用 > 6 dB |
| **穿越频率 fc** | `|GH| = 0 dB` 的频率 | 一般为开关频率的 1/10 ~ 1/20 |

**注意 fc 取的是最后一个 0 dB 穿越点**（高频侧那个），不是第一个。
这个选择在 02 文档有依据；如果你的环路有多个穿越点，
读数会和你肉眼找的第一个点不一样，这是预期行为。

**饱和点会被剔除**：顶到轨后输出不再线性跟随注入，测出的"增益"
只是限幅器的增益，与真实环路无关。告警条会告诉你剔除了几个点。

### 6.2 曲线信息

| 项 | 含义 |
|---|---|
| 频点 | 已完成 / 总点数 |
| 注入幅值 | 当前配置值 |
| 每周期采样 | `f_s / f_act`，低于 4 标"偏低" |
| LSB 对照 | 注入峰值相当于几个 ADC LSB，< 10 提示偏高噪声风险 |

**关于 LSB 对照**：它**只算 ADC 量化**，不含开关纹波、参考噪声、
注入失真——而这三样在扫频前一个都测不到。所以它是一个"下限提示"，
不是"信噪比"。早期版本叫"预计 SNR"，因为看着精确实际无依据，已降级。

### 6.3 告警

三类：

| 颜色 | 类型 | 处置 |
|---|---|---|
| 灰 | 提示 | 无需动作，知道就行 |
| 橙 | 警告 | 能扫但不可信，建议改参数 |
| 红 | 错误 | 不能扫 / 扫失败了 |

## 6.5 串口日志面板（右栏底部）

设计稿：`design/sfra-console-mockup.html`。位置在右栏最底下，**不挤压图表**
（折叠时只占一行）。

### 6.5.1 它解决什么问题

| 以前的状况 | 现在 |
|---|---|
| 所有日志只进状态栏 `showMessage`，8 秒后被下一条顶掉 | 500 行滚动历史，往上翻能看到几分钟前发生了什么 |
| 出问题只能靠 SecureCRT 抢串口——而串口是**独占**的，一抢上位机就断 | 面板复用同一条链路，不新建串口，上位机不受影响 |
| 不知道 MCU 到底回了什么，只能靠猜 | 每一帧应答都带时间戳（到毫秒）和解析后的内容 |

### 6.5.2 各部件

| 部件 | 说明 |
|---|---|
| **标题栏** | 点一下折叠/展开。左边状态点：灰=未连接，绿=已连接；中间是 `端口 · 波特率`；右边是行数（折叠时若有过错误会变成红色的 `N 行 · M 错误`） |
| **过滤 chip** | `全部 / TX / RX / ERR / SYS`，点一下只看该类。chip 上的数字是**当前缓冲区里**各类的条数 |
| **日志区** | 分色：`TX` 蓝（我发的）、`RX` 绿（它回的）、`ERR` 红（错误，带浅红底）、`SYS` 灰（系统） |
| **快捷命令** | `ping` / `caps` / `conditions` / `status` / `coeff` / `abort`，点一下即发 |
| **输入框** | 手动敲命令，↑↓ 翻历史 |

### 6.5.3 三个容易误解的地方

**① 为什么默认看不到 `GET_STATUS` / `GET_DATA`？**

它们是扫描中的内部轮询，200 ms 一次，一次扫频几十上百条。全记下来会把
你真正想看的应答（ACK / NAK / CAPS）冲走。点过滤行右侧的
**「显示TX」** 就能把它们也放出来——**查时序问题时必开**，因为
"什么时候发的、什么时候回的"只有在完整收发对照里才看得清。

**② 为什么扫频中发送框是灰的？**

不是做漏了，是**故意的**。固件有 500 ms 看门狗：连续 500 ms 收不到任何
有效帧就自动 ABORT。而 `GET_DATA` 与 `GET_STATUS` 在 MCU 主循环里是
同一次 poll 的竞争者——你在中间插一条命令，可能把 `GET_DATA` 挤到下一个
周期，上位机这边就表现为取数变慢甚至越界。扫频结束后自动解禁。

**③ 为什么没有 `help` / `sfra cost` 这些命令？**

设计稿里有，但**当前固件没有 ASCII shell**——`sfra_proto.c` 只认二进制帧，
`SOF = 0xAA55` 之外的字节全被丢进 resync 统计。硬发 ASCII 文本只会得到
超时，所以面板只提供**协议命令表里真实存在的**六条。

> 固件将来加了 shell 时，只需在 `console.py` 的 `parse_command()` 里
> 加一条"裸文本走 ASCII 通道"的分支，面板其余部分不用动。

### 6.5.4 出问题时怎么用它

| 现象 | 看哪里 |
|---|---|
| 卡在某个百分比 | 开「显示TX」，看最后一条 `→ GET_DATA idx=N n=M` 与 MCU 回的 `STATUS idx=K` 是否对得上；若出现 `← NAK GET_DATA：INDEX_RANGE` 就是越界（坑 A18） |
| 扫频开始就失败 | 看 `← ACK SET_CONFIG` 有没有出现；没有就是配置被拒，`ERR` 行会写错误码 |
| 握手不通 | `ping` 之后有没有 `← PING_ACK`；没有就是物理层/波特率问题 |
| 想知道固件的真实状态 | 点 `status` 快速取一次；**扫频中慎用**，理由同 ② |

### 6.5.5 实现边界（给维护者）

- **不抢协议字节**。面板只旁听 `BaseLink.frameIn` / `frameOut` / `logText` /
  `errorText`，不参与分帧、不消费字节流。面板出任何 bug 都不会影响扫频。
- **缓冲区上限 500 行**，超出丢最旧的，计数同步递减。
- **性能**：插入用 `QTextCursor` + 预缓存的 `QTextCharFormat`，
  不用 `insertHtml`——后者实测 28 ms/行，一次扫频就是几十秒的卡顿；
  现在 0.29 ms/行。过滤重排用 `beginEditBlock()` 包住，11 ms / 500 行。
- 守门测试：`src/tests/test_console_panel.py`（24 项）。

## 7. 完整操作流程（第一次用）

```
① 启动 → 确认顶栏显示"仿真"或"已连接 COMx"
② 左栏：模式选 Plant，起点 100 Hz，终点 20 kHz，20 点/decade，Normal
③ 左栏：ISR 频率填你固件的真实值（仿真模式必填，真机自动读）
④ 按「开始扫频」→ 等进度到 100%
⑤ 右栏看告警：有橙色"饱和"或"采样偏低"就先解决
⑥ 对照本文 §8 的基准曲线，确认形状对得上
⑦ 切到 Loop Gain 再扫一遍 → 看 PM / GM / fc
⑧ 「导出」存一份基线，以后参数改动可以对比
```

**第 ⑥ 步是最容易被跳过、也最重要的一步。** 跳过它，你只能看到
"PM = 52°，看起来不错"，但没法回答"这个 52° 是真的吗"。

## 8. 怎么知道"测出来的是对的"——真实基准

扫频只回答"测到了什么"。要判断"测得对不对"，需要一份**独立于
测量过程**的基准。工具里有：

```bash
# 二阶 LC，f0=1300, Q=2，归一化（直流 0 dB）
.venv\Scripts\python.exe tools\bode_reference.py

# 真实 Buck，Vin=12V（直流 +21.6 dB）
.venv\Scripts\python.exe tools\bode_reference.py --vin 12

# 一阶低通（S6a 那个被测对象）
.venv\Scripts\python.exe tools\bode_reference.py --kind lp1 --fc 1000
```

输出四组东西：

| 输出 | 内容 |
|---|---|
| 终端表格 | 每个频点的连续域 / Tustin / 偏差 |
| `bode_reference.csv` | 同上，可导入 Excel |
| `bode_reference.png` | 三条曲线 + 参考线，直接看图 |
| 自洽判据 | 4 条 PASS/FAIL，验证基准本身算对没 |

三条曲线的含义：

| 曲线 | 数学 | 意义 |
|---|---|---|
| **连续域解析解** `H(s)` | `K/(1+s/(Qω0)+(s/ω0)²)` | **物理对象本身**。这就是"真实应该长什么样" |
| **Tustin 离散** `H(z)` | `z = e^{jωTs}` 代入差分方程 | **MCU 数字滤波器实际在算的** |
| **ZOH + 一拍延迟** | `z⁻¹·(1−e^{−sTs})/(sTs)·H(s)` | **真实数字环路**（S6b 功率级用） |

三条曲线的关系：

- **低频段三者重合**（差 < 0.1 dB）→ 离散化在低频无害
- **越往高频，Tustin 越偏离连续域**（f_s/5 处低 2.5 dB @二阶）
  → 这是双线性变换的**频率翘曲**，数学必然，不是实现 bug
- **ZOH+延迟比连续域多滞后 108°**（20 kHz @100 kHz）
  → 这就是数字电源相位裕度总比想象中小一半的原因

详细数值（二阶 LC，f0=1300，Q=2，fs=100 kHz）：

| f (Hz) | 连续域 | Tustin | 差 | 相位差 |
|---|---|---|---|---|
| 100 | +0.045 dB | +0.045 dB | 0.000 | 0.00° |
| 1300 | +6.021 dB | +6.016 dB | −0.005 | −0.13° |
| 10 000 | −35.31 dB | −35.91 dB | −0.59 | −0.13° |
| 20 000 (f_s/5) | −47.45 dB | −49.98 dB | **−2.53** | −0.25° |
| 49 000 | −63.05 dB | −115.67 dB | **−52.6** | −0.72° |

**这张表怎么用**：

- 你扫出来高频段比理论低 2~3 dB → **正常**，是翘曲
- 低 10 dB 以上 → 有问题（每周期采样点太少 / 整周期取整错 / 相位步进错）
- 低频段差 0.1 dB 以上 → 一定有问题（低频翘曲可忽略，必是实现错）

## 9. 补偿器页（Tab 2）简介

只做三件事：

1. 输入 Kp / Ki，实时算预测的幅相并叠在图上（紫色线）
2. 把系数**下发**到 MCU（`SET_COEFF` 命令）
3. 从 MCU **读回**当前系数

细节见 05 文档 §5.3。唯一需要在这里强调的是：

**Ki 的单位是 1/s（连续域积分增益），不是"每次加多少"。**
离散时要乘 `Ts = 1/fs`。如果在 MCU 里直接写 `I += Ki*e`，
实际生效值是 `Ki/Ts`，在 100 kHz 下放大了 10⁵ 倍，必然发散。
这是新手最常踩的坑，`plants.PICompensator` 的注释里专门写了。

## 10. 常见问题速查

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| 预计点数比手算少 | f_s/5 截断 | 看「预计 N 点」是否变橙；提高 ISR 或降低终点 |
| 进度条停在某个数不动 | 频点采集超时 / 丢帧 | 见 §4.5 排查顺序 |
| 曲线右端突然消失 | 高频置信度不足，被剔除 | 正常；想多看就把终点调低 |
| 高频段比理论低好几 dB | Tustin 翘曲 | 正常；f_s/5 处二阶约 −2.5 dB |
| 相位出现正值（> 0°） | 复数约定实现反了 | 全项目只应在 `bode_data.z_from()` 实现 `Z = S_c − j·S_s` |
| 全频段曲线水平 | 注入没生效 / 幅值太小 | 查「注入幅值」的 LSB 提示；加大幅值 |
| PM 看起来特别大（>90°） | 饱和导致增益压缩 | 看橙色饱和告警条；降幅值重扫 |
| 仿真曲线和真机高度差一个常数 | 仿真用归一化形式（直流 0 dB） | 正常；真实 Buck 直流增益 = Vin |
| 选了 Plant 但结果像 Loop | 注入点接错（接在误差后 vs 参考上） | 查 05 文档 ISR 模板那两行 |

## 11. 一页速记

```
起点/终点    = 扫哪一段（终点被 f_s/5 截断）
点数/decade  = 扫多密（20 够用，看清峰值要 40）
精度         = 每点多积几个周期（验收只认 Normal）
注入幅值     = 灌多大劲（小到噪声、大到饱和，找中间）
ISR          = 告诉上位机固件跑多快（算上限/取整/f_act 全靠它）
被测对象     = 只在仿真模式有效，真机忽略
预扫         = 自动找谐振峰，反推安全幅值
进度条卡住   = 后端没送新点，不是进度条算错
PM/GM        = 结论；左边的参数是前提，前提不成立结论没意义
```
