## 1. 一句话说清"验收"是什么

**验收不是"曲线看起来正常"，而是"我测出来的每个点，都能被一个
独立于测量过程的数学量解释"。**

扫频工具最危险的失败模式不是报错或空图，而是**静默错误**：

| 静默错误 | 表面现象 | 实际后果 |
|---|---|---|
| 相位符号反了 | 曲线很平滑、很"漂亮" | PM 从 45° 报成 135°，系统实际会振荡 |
| 整周期取整错 | 低频段有轻微毛刺 | 增益偏差 3~10 dB，谐振峰被削 |
| Tustin 当连续域比 | 高频低 2.5 dB 判 FAIL | 正确固件被误判，白查一周 |
| 饱和点没剔除 | PM 偏大 | 按这个参数上线会失稳 |
| 仿真归一化当基准 | 和真机差 21.6 dB | 怀疑接线、怀疑 ADC、怀疑一切 |

这些都没有异常提示。**只有分层比对能抓出来。**

## 2. 核心方法：三条曲线，互不撒谎

任何一个频点，我们手上有**三个独立的数**：

```
        ①连续域解析解          ②Tustin 离散           ③扫频实测
        H(s) = K/(1+...)      H(z), z = e^{jωTs}     MCU 真跑出来的
             │                      │                     │
             │  ← 数学翘曲 →        │   ← 实现误差 →      │
             └──────────────────────┴─────────────────────┘
                        ↑                        ↑
                    （已知，可算）          （被测，要判）
```

**判据设计的关键在于两组"已知偏差"必须提前算出来**：

| 偏差来源 | 大小（二阶 LC, fs=100 kHz） | 性质 |
|---|---|---|
| 数学翘曲 ①→② | 低频 0 dB，f_s/5 处 **−2.53 dB**，f_s/2 处 → −∞ | 必然存在，不是 bug |
| 实现误差 ②→③ | 目标 **< 0.5 dB / 1.5°** | 这才是要抓的 |
| ZOH + 一拍延迟 | f_s/5 处额外 **−108°** 相位 | 真实环路固有 |

**所以验收逻辑是**：

> ③ 与 ② 的差 → 判固件/上位机实现对不对（严格：0.5 dB / 1.5°）
> ② 与 ① 的差 → 确认"知道自己在偏离什么"（不用判，只记录）
> ③ 与 ① 的差 → 只在低频段判（1 dB / 3°），因为那里翘曲 ≈ 0

把 ③ 直接跟 ① 全频段比，是**最常见的验收设计错误**——它会让
数学正确的实现被判 FAIL。

## 3. 四关验收（每关是 gate）

```
第 0 关   基准自洽      ← 基准本身对不对？（不需要硬件）
   │      tools/bode_reference.py 的 4 条判据全 PASS
   ▼
第 1 关   L0 全绿       ← 算法对不对？（不需要硬件）
   │      pytest 全过 + 仿真曲线与基准在低频段一致
   ▼
第 2 关   S6a 一阶低通  ← 定点/浮点在目标 MCU 上对不对？（需要真板）
   │      误差 < 0.5 dB / 1.5°（vs Tustin），ISR 开销 < 10% / 20%
   ▼
第 3 关   S6b 真实 Buck ← 接真功率级，与含 ZOH+延迟的模型比对不对？
          < 3 dB / 5°，且改参数后变化方向正确
```

**顺序不能跳。** 跳过第 0 关，后面三关的判据可能全建在错的基准上；
跳过第 1 关，"MCU 上的误差"会同时包含算法错与移植错，查不出来。

## 4. 第 0 关：基准自洽

**目的**：证明我们手上的"真实 Bode 图"没算错。

**怎么跑**：

```bash
.venv\Scripts\python.exe tools\bode_reference.py
```

**判据**（脚本自动打 PASS/FAIL）：

| # | 判据 | 阈值 | 不通过说明什么 |
|---|---|---|---|
| 1 | 低频段两域一致（f ≤ f0） | < 0.10 dB / 1.0° | Tustin 系数算错 |
| 2 | f_s/5 处翘曲为**负** | 必须 < 0 | 频率轴映射方向错（s ↔ z 反了） |
| 3 | 直流增益 = K | ±0.01 dB | 分子归一化错（最常见：K=Vin 漏乘） |
| 4 | f0 处 = K·Q / −90° | ±0.10 dB / ±1.0° | 阻尼项系数错 |

**这一关的价值**：它用**手算就能验的闭式结果**（−3.01 dB、20log10(Q)、
−90°）来约束基准实现。任何一条 FAIL，说明 `sim/theory.py` 有问题，
此时第 1~3 关的数据全部作废。

**已锁进单测**：`src/tests/test_theory.py` 共 28 项，把上表每个
数字都用 `pytest.approx` 钉死，包括：

- `f_s/5` 处 Tustin 翘曲 = −1.259 dB（一阶）/ −2.53 dB（二阶）
- 一阶 Tustin 直流增益**精确为 1**（分母 `1+a1z⁻¹` 而非 `1−a1z⁻¹`）
- `theory.TustinLC` 与 `plants.SecondOrderLC` **系数逐位一致**
  + 200 拍时域响应逐拍一致（防止两处实现漂移）

> **这一关是 v1.1 新增的。** 之前只有"跟解析解比"这一条路，
> 而解析解本身没有第二个人校验过。现在基准与实现互为约束。

## 5. 第 1 关：L0 全绿（不需要硬件）

**目的**：证明算法（整周期取整、θ 递推、复数约定、PM/GM 计算）对。

**怎么跑**：

```bash
# 全量单测
.venv\Scripts\python.exe -m pytest -q
# 期望：175 passed / 39 deselected

# C 库交叉验证（L1，可选但建议）
.venv\Scripts\python.exe -m pytest -m crosscheck -q

# 仿真 vs 基准的定点比对
.venv\Scripts\python.exe tools\bode_reference.py --no-plot
```

**判据**：

| 项 | 阈值 | 说明 |
|---|---|---|
| 单测全过 | 0 failed | 含 28 项基准自洽 + 147 项原有 |
| 扫频仿真 vs 连续域，f ≤ f0 | **< 0.1 dB / 0.5°** | 低频无翘曲，必对齐 |
| 扫频仿真 vs 连续域，全频段 | < 3 dB | 含翘曲，仅记录不判 |
| 相位全程为负（一阶低通） | 无正值 | 出现正值 = 复数约定反了 |
| 高频斜率（一阶/二阶） | −20 / −40 dB/dec ±2 | **量实测值**，不是量理论值 |

**关于"量实测值"**：06 文档记过一次假判据——斜率判据拿理论曲线算，
无论固件输出什么恒为 −20.8 dB/dec，永远 PASS。**写判据时基准必须
独立于被测物**，这是硬规则。

**这一关的实测基线**（`tools/bode_reference.py` 默认参数）：

```
f ≤ f0 段：max 0.005 dB / 0.127°
全频段  ：max 2.089 dB / 0.232°
```

全频段的 2.089 dB 就是翘曲，属于预期。

## 6. 第 2 关：S6a 一阶低通（需要真板）

**目的**：证明定点/浮点在**目标 MCU** 上数值正确、ISR 开销可接受。

**被测对象**：`filter_rc.h` 的一阶低通，不接功率级。
这样"被测对象"和"固件"都是已知的，出错必在移植。

**怎么跑**（详见 `06_S6a上板接入指南.md`）：

```bash
# 1. 烧固件（示例：STM32）
# 2. 逐级确认能通
python tools\selftest_s6a.py --port COM7 --fc 1000
```

**判据**（脚本自动判）：

| # | 判据 | 阈值 | 抓什么 |
|---|---|---|---|
| A | 与 **Tustin 离散域** 比（全频段） | **0.5 dB / 1.5°** | 固件实现 bug |
| B | 与 **连续域** 比（f ≤ 10·fc） | **1 dB / 3°** | 物理对象偏离 |
| C | 相位符号全负（0° → −90°） | 无正值 | 复数约定 |
| D | 相位单调 | 无上翘 | θ 递推错 |
| E | fc 处 −3 dB / −45° | ±1.5 dB / ±6° | 特征点 |
| F | 高频斜率 | −18 ~ −22 dB/dec | 阶数对不上 |
| G | ISR 附加开销 | M4F < 10%，M0+ < 20% | 实时性 |

**A 与 B 为什么要分开**（06 §6.4 完整解释）：

固件用 Tustin，它在 f_s/5 处比连续域低 **1.26 dB**。如果只拿连续域
当基准，一个**数学完全正确**的固件会在 20 kHz 判 FAIL。

所以：
- 判"固件有没有 bug" → 跟离散域比（A，严格）
- 判"物理对象对不对" → 跟连续域比（B，只限低频段，那里翘曲 ≈ 0）

**A PASS 而 B FAIL 的含义**：固件忠实地实现了 Tustin，但你的 fc
可能设错了，或者那根本不是一阶 RC。

**A FAIL 而 B PASS 的含义**：低频对、高频错 → 查整周期取整与 θ 递推。
高频每周期采样点少，取整误差被放大最快。

**G 怎么量**（不能靠猜）：

```c
// 最硬的证据：GPIO 翻转 + 示波器
GPIO_BSRR = PIN;          // 进入
sfra_inject(&s); sfra_monitor(&s, ...); sfra_advance(&s);
GPIO_BSRR = PIN << 16;    // 退出
```

或用 `DWT->CYCCNT`。**注意先确认 CYCCNT 真的在动**——见过量出
"0 周期"的情况，那是 DWT 没使能。

## 7. 第 3 关：S6b 真实 Buck（需要功率级）

**目的**：证明整套东西在真实功率级上成立，且**因果关系正确**。

**被测对象**：真 Buck（Vin=24V → Vout=12V，或你的实际工况）。

**模型基准**（`tools/bode_reference.py --vin 24`）：

```
H_eff(z) = z⁻¹ · (1−e^{−sTs})/(sTs) · Vin/(1 + s/(Qω0) + (s/ω0)²)
           ↑     ↑                       ↑
         延迟   ZOH                   功率级（含 Vin 增益）
```

**三个要素都不能省**，尤其后两个：

> 不建 ZOH 和延迟项，实测高频段必然比模型"差"，会被误判成算法错。
> 这是数字控制 Bode 最经典的坑（04 文档 §4.5 Step 3）。

**判据**（分四步，每步是独立的 gate）：

### Step 1 · 扫 Plant（开环）

| 检查 | 判据 |
|---|---|
| 低频增益 | = 20log10(Vin) ± 1 dB（**这是 Vin 增益，不是 0 dB**） |
| 谐振峰 | 出现在 f0 ± 20% 内，高度 ≈ 20log10(Q) ± 3 dB |
| 高频斜率 | −40 dB/dec ± 4 |
| 与含 ZOH+延迟的模型比 | **< 3 dB / 5°** |

### Step 2 · 扫 Loop Gain（闭环）

| 检查 | 判据 |
|---|---|
| 低频 | 高增益、−20 dB/dec（积分作用） |
| 穿越 | 0 dB 处斜率 ≈ −20 dB/dec |
| PM | 与阶跃响应观察到的稳定程度**量级一致** |
| 饱和 | 无饱和告警条；扫频期间临时放宽补偿器输出限幅 |

### Step 3 · 因果验证（最强证据）

| 改动 | 期望变化 | 判据 |
|---|---|---|
| Ki 减半 | 低频增益 −6 dB | 方向必须对，幅度 ±2 dB |
| Kp 翻倍 | fc 上升、PM 下降 | 方向必须对 |
| 负载电流 × 2 | 谐振 Q 下降 | 方向必须对 |
| 幅值 A 与 2A 各扫一次 | 两条曲线重合 | < 1 dB / 3° |

**第四条（双幅值）最值得做**：不重合说明非线性（靠近 DCM、
饱和、限幅没放宽）。而 PM 一旦在非线性区测出来，就毫无意义。

**为什么"方向对"比"数值准"更硬**：绝对数值可能受寄生参数、
探头、pu 标定影响；而"Ki 减半 → 低频掉 6 dB"是系统结构的
直接推论，错了就是通路接错。

### Step 4 · 存基线

Vin / Vout / Iout / 温度 / 补偿器系数 / pu 标定系数全部进 `meta.json`。
同一台机器以后复测，偏离 > 3 dB 就查硬件（电容老化、电感饱和、
驱动退化）。这是 TI 手册说的"周期性健康诊断"用途。

## 附：为什么基准里必须有三条曲线

经常被问："直接和 theory 比不就行了，为什么画三条？"

因为**三条曲线回答三个不同的问题**：

| 问题 | 该看哪条 |
|---|---|
| 物理上应该是什么样？ | 连续域 ① |
| MCU 数字滤波器应该输出什么？ | Tustin ② |
| 真实数字环路（含 ZOH/延迟）应该是什么样？ | ZOH ③ |
| 我的实现有没有 bug？ | ③实测 vs ② |
| 我的离散化偏差有多大、可接受吗？ | ② vs ① |
| 我的模型是不是漏了东西？ | ③ vs ② |

少一条，就会有一类问题无法回答。
