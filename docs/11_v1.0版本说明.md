# SFRA v1.0 版本说明

> 定版时间：2026-11-24
> 适用硬件：PY32F071（Cortex-M0+，72 MHz，无 FPU）
> 状态：**软件链路已验证，待接真实功率级**

---

## 一、这个版本能做什么

在**软件二阶 LC 模型**作为被测对象的条件下，完整跑通：

1. 上位机下发配置 → MCU 扫频 → 回传原始数据 → 上位机画 Bode 图 → 导出 CSV
2. 扫频范围 100 Hz ~ 2 kHz（`f_max = f_s / 5`，`f_s = 10 kHz`）
3. 点数可配，默认 40 pts/decade，100~2000 Hz 共 53 点
4. ISR 占用实测 **avg 1312 cycle / 7200 预算 = 18%**

### 对账结果（2026-11-24，PLANT 模式，40 ppd，28 点）

| 指标 | 实测偏差 | 判据 | 结论 |
|---|---|---|---|
| 幅值最大偏差 | **0.039 dB** | < 1 dB | 通过 |
| 幅值 RMS | 0.014 dB | — | 通过 |
| 相位最大偏差 | **0.701°**（末点 2000 Hz） | < 3° | 通过 |
| 相位 RMS | 0.147° | — | 通过 |
| 超限点数 | 0 | 0 个 | 通过 |

被控对象理论模型（Sallen-Key，ω0 = 2π·1000，Q = 1/3）：

```
H(s) = ω0² / (s² + 3·ω0·s + ω0²)
```

Tustin 离散化，`k = 2·f_s`，`α = ω0/k`，`β = ω0/(Q·k)`。

> 末点 0.701° 的来源已定位：Q15 定点路径在 `f_s/5` 处量化噪声最大，
> 贡献约 0.2°，其余来自 sin 表插值与累加器舍入。属于数值极限，
> 不是算法错误。

## 三、本版本修复的问题

### 1. 100 Hz 首点报 `nan`

**现象**：CSV 第 0 点 `Mag(dB)` / `Phase(deg)` 全为 `nan`。

**根因**：`sfra_dut_reset()` 定义在 `sfra_dut.c:249`，但全工程从未调用。
上一轮扫频结束时二阶滤波器还留着 `d1/d2`，下一轮首点从带残留状态起步。
首点 settle 只有 `max(20ms, 2 个注入周期)`，100 Hz 时正好 20 ms，
不足以完全吞掉这份残留。

**修复**：`sfra_app.c` 中 ISR 由停转启的边沿调用 `sfra_dut_reset()`。
放在这里而不是 `do_start()`，是因为后者会把 `sfra_dut.h`（依赖 `bsp.h`）
拉进协议层，破坏"协议层不依赖被测对象"的分层。

**注意**：此修复只解决"残留污染"。若首点**仍然**为 `nan`，说明采集窗口
根本没有运行（ISR 未启动 / 主循环未推进），那是另一类问题。

### 2. Keil 链接 `L6200E: multiply defined`

`sfra_proto.c` 里 `sfra_proto_set_coeff` / `get_coeff` / `get_conditions`
三个弱符号在 ARMCC 下失效（`#if defined(__GNUC__)` 分支不成立）。

**修复**：改为
```c
#if defined(__CC_ARM)
#define SFRA_WEAK __weak
#elif defined(__GNUC__) || defined(__clang__)
#define SFRA_WEAK __attribute__((weak))
#else
#define SFRA_WEAK
#endif
```

### 3. 假 MCU 只扫 20 点 / e2e `assert 20 == 21`

STATUS 的 `freq_index` 口径与 `GET_DATA` 的 `avail` 不一致。
**修复**：DONE 时按 `vec_length` 上报，与 `avail` 统一。

## 四、本版本**没有**做的事（明确边界）

1. **没有接真实功率级**。当前测的是 MCU 内部的软件二阶 LC，
   不是真实电路。这一步等功率板到位。
2. **没有用 LOOP 模式**。S6a 阶段闭环不存在，`Y ≈ Inj` 导致
   `GH = Y/(Inj−Y)` 分母趋零，测出来是 `1/jω` 的数值残差。
   **一律用 PLANT 模式。**
3. **没有验证穿越频率和相位裕度**。扫频上限 2 kHz 来自 `f_s/5`，
   而实际功率级穿越点通常高得多。要测 PM/GM 必须先提 `f_s`。
4. **文本 shell 通路保留未删**。见下方开关说明。

## 五、配置开关

全部在 `SFRA/sfra_local_cfg.h`：

| 开关 | 当前值 | 说明 |
|---|---|---|
| `SFRA_LOCAL_MEASURE_ISR_COST` | 0 | ISR 开销测量。测完保持 0，打开会让每拍多 30~40 cycle |
| `SFRA_LOCAL_USE_FIXED_POINT` | **1** | M0+ 无 FPU，**必须为 1**。float 路径实测占 96% 且超时 |
| `SFRA_LOCAL_USE_TEXT_SHELL` | 1 | 文本 shell 分流器。置 0 可关掉，上位机不受影响 |

> `SFRA_LOCAL_USE_TEXT_SHELL` 是 v1.0 新加的。置 0 后
> `sfra_app_feed_byte()` 不再判断帧头，字节直接进协议层，
> shell 的 `help` / `sfra` 命令失效，二进制协议与上位机行为完全不变。
> 默认保持 1，是为了不在这份归档版本上改动主循环契约。

## 七、关于 libsfra 的调研结论

调研对象：https://github.com/Frank-zheng-C/libsfra

| | libsfra | 本工程 |
|---|---|---|
| 总行数 | 560 行（含测试） | 约 2700 行（含注释） |
| 文件数 | 4 个 + 1 个头 | 13 个 |
| 通信层 | **完全没有**（readme 里是 `T.B.D.`） | 完整（10 个命令） |
| 幅相计算 | MCU 上算（`log10` + `atan`） | PC 上算 |
| 周期数策略 | 3 个分支 | 3 档 + `SFRA_MIN_SPC` 下限 |
| 首点保护 | 无 | v1.0 已修 |

**结论：不替换。** 理由：

1. libsfra 把"数据怎么传到 PC"留成了 `T.B.D.`，接 MODBUS 仍要自己写，
   等于没省掉工作。
2. 它的算法并不比本工程强（`calc_cycles` 只有 3 个分支，无 settle 保护）。
3. 本工程的 0.039 dB / 0.235° 对账结果已经验证过，换核心等于作废重验。

**真正该精简的是通信层而不是算法层**，但本版本为了控制风险没有动它。

## 八、下一步（接功率板后）

1. **改 `sfra_pend.c` 的 ISR**，把 `sfra_dut_step_q15(inj)` 换成
   "注入叠到占空比/参考 → 读 ADC"，然后删除 `sfra_dut.c/h`。
2. **确认注入幅值**。真实功率级注 10% 会触发 OVP，通常 1~2%。
3. **确认扫频期间工作点稳定**。53 点约 1.1 s，期间光伏输入和负载不能变。
4. **提高扫频上限**（可选）。10 kHz 上限需 `f_s = 50 kHz`，
   ISR 预算 1440 cycle，而实测已用 1312，**非常紧但可能**。
   100 kHz 上限需 `f_s = 500 kHz`（144 cycle/拍），M0+ 不可能。
   **不要改 `SFRA_NYQ_DIV`**——降到 2.5 会让 Tustin 频率畸变超 1%。
5. **闭环稳定后切 LOOP 模式**，读穿越频率、相位裕度 PM、增益裕度 GM。
